# 叙事架构：你的故事 + 项目深挖 + 自我介绍 + 黑话校准

这份文件是 skill 最重的一根骨头。**面试输赢的核心不是"答得对不对"，是"你给对方留下了一个怎样的人**。这件事**只有靠叙事工艺**能完成。

---

## ① 叙事主轴（The Spine）

### 概念
你的简历过了，意味着对方愿意花 30-90 分钟听你讲一个故事——**你这个人为什么是这个 JD 的解**。这个故事就是叙事主轴。

主轴**不是简历摘要**——简历是"我做过什么"，主轴是"为什么我做这些事在这一刻汇聚成了'我适合这个岗位'"。

### 主轴的三个要素

```
主轴 = （你的"为什么")  +  (你过去的"主旋律")  +  (这家公司是这个故事的"下一站")
```

例子（针对火山方舟 AI Application 解决方案 PM 实习）：

> 我的主轴：**"我一直在做'把模型能力翻译成行业语言'这件事——本科做过 NLP 相关的项目，研究生阶段在 X 实验室做了 RAG 在医疗场景的落地，这一路走下来我发现真正的瓶颈不是模型，是 PM 对业务和模型边界的双向 sense。火山方舟现在做的就是把豆包和 VikingDB 这套能力下沉到电商、视频、新闻这些垂类——这正好是我'翻译'能力能往大平台规模化的下一站。"**

注意这段没有：
- 没说"我对贵公司很向往"——这是商业关系，不是粉丝告白
- 没说"我有很多优秀品质"——优秀不优秀对方自己判断
- 没说"我会很努力"——废话

它有的是：
- **一个清晰的"我一直在做的事"**（翻译模型能力）
- **过去的轨迹自洽**（NLP → RAG 落地）
- **目标公司的具体业务**（豆包、VikingDB、垂类）
- **下一站的逻辑闭环**（个人能力 × 公司战略 = 自然的下一步）

### 主轴怎么提取（给用户用）

skill 在 L1 战略层这一步要引导用户做：

1. **找你的"主旋律"**——把简历从头到尾扫一遍，问自己："这些项目背后我反复在做的事是什么？"（不是"我用过什么技术"，是"我反复在解决什么问题"）。
2. **看 JD 的"主战场"**——这家公司这个岗位，3 个月内最重要的事是什么？
3. **找两者的交集**——你的主旋律和 JD 主战场重叠的那个点，就是叙事主轴的着陆点。

### 主轴的"三档"

**弱**："我学过 LLM、做过项目、希望加入贵公司学习。" —— 通用得像填空题。
**合格**："我研究生阶段做过 RAG 项目，对大模型应用感兴趣，希望来火山方舟做 AI 解决方案。" —— 信息有了但没主旋律，没"为什么是这一刻"。
**惊艳**：见上面"我的主轴"示例 —— 有"主旋律 + 公司战略 + 下一站"三件套，逻辑自洽。

## ② 三个传递目标形容词

### 概念
面试结束后，面试官会跟 HR 用 1-3 句话描述你。**这句话用了什么形容词，决定了你过不过**。

主动选 3 个你想被记住的形容词，反推所有应对。

### 选词原则

- **必须扣 JD**：你的形容词要和 JD 的隐含期待对应
- **互相互补**：3 个词覆盖三个维度——一个偏能力（你能干什么）、一个偏品性（你是怎样的人）、一个偏稀缺性（为什么不容易找到）
- **避免空泛词**：积极、努力、有责任心——这些不算形容词，是默认设置

### 例子（火山方舟 AI Application 实习）

JD 隐含期待：能配合做 GTM、写好材料、懂模型边界、能扛客户。

可选 3 词：
- **能力维度**："会翻译"——能把模型能力翻译成业务语言（核心稀缺）
- **品性维度**："不掉链子"——交付靠谱、能扛客户、不让 leader 操心（实习生最紧缺品质）
- **稀缺性维度**："有产品 sense 的技术人"——既懂 RAG 实现也懂为什么客户要 RAG（这是 AI PM 真正稀缺的混合属性）

每个建议、每个回答、每段话术，都要往这 3 个词上靠。如果某段话术不能让对方记住这 3 个词中的一个——删掉它。

### 反例

❌ 选了"积极、勤奋、有责任心"——这是默认设置，所有人都这样。
❌ 选了"创新、颠覆、改变世界"——和实习岗位的 stake 不匹配，显得不自知。
❌ 选了 5 个词——人脑记不住 5 个，3 个是上限。

## ③ 项目深挖（3 层讲法）

### 为什么要 3 层
面试官问"讲讲你这个项目"——大部分人只讲第 1 层（事实层），有些讲到第 2 层（方法层），但**真正拉开档次的是第 3 层（哲学层）**。

```
第 1 层：事实层（What）
- 我做了什么、用了什么技术、有什么数据
- 占讲述时间 30%
- 这一层只是"我没说谎"的证明

第 2 层：方法层（How）
- 在哪些权衡上做了什么选择，为什么不选其他选项
- 占讲述时间 50%
- 这一层证明"你有结构化思维"

第 3 层：哲学层（Why this approach）
- 这个项目让你形成了什么"方法论原则"，下次类似问题你会怎么处理
- 占讲述时间 20%
- 这一层证明"你不是按部就班的工人，是有思考密度的设计者"
```

### 3 层讲法示范（一个 RAG 项目）

**❌ 只有第 1 层（弱）**：
"我做过一个医疗领域的 RAG 项目，用 LangChain 搭的，向量库用的 ChromaDB，模型用 ChatGPT，效果还可以。"

→ 信息密度低，听完面试官只能问"那你怎么做 eval"。

**⚠️ 1+2 层（合格）**：
"我做了一个医疗 RAG 项目，目标是回答医生问诊时的临床指南问题。技术上踩过几个坑：(1) chunk size 选择——太小导致上下文断，太大导致 retrieval 噪音，最后用了 800 tokens + 200 overlap；(2) embedding 模型选——通用 embedding 在医疗术语上召回率低，最后换成了 BGE-M3 微调版；(3) eval 方法——一开始用 hit rate@5，后来发现这个指标和医生满意度脱节，改成了人工标注 200 对 'query-good answer' 做 LLM-as-judge。"

→ 有思考有权衡，合格。

**✅ 1+2+3 层（惊艳）**：
"...（同上 1+2 层内容）...

**这个项目让我形成了一个原则：RAG 的瓶颈很少在 retrieval 本身，大多在 eval。**

具体来说——RAG 不是一个搜索问题，是一个'我的搜索结果到底对终端用户有没有用'的问题。第一次跑 hit rate@5 时分数 70+，自我感觉良好；但拿给三个临床医生试用，他们说'前 3 个结果都是相关文献，但都没回答我真正想问的问题'。**这件事让我意识到所有'代理指标'都有偏移**——后来我做任何 AI 应用，第一件事就是先和真实用户做 30 分钟的'看他用'再设计 metric，这套方法迁移到我后续做的另外两个项目里都直接 work。

如果让我现在重做这个项目，我会更早投入时间在 eval pipeline 上——这是我现在面对任何 RAG/Agent 系统的第一性原则。"

→ 这一段把项目从"我做过 X"升级到"我从 X 中提取了原则、原则可迁移、原则在新项目里得到验证"——**这才叫思考密度**。

### 失败叙事工艺（最高频考点）

"讲一次失败" / "你最大的失败" / "讲一个被砍掉的项目" —— 这是 AI PM 面试的高频考点。失败叙事**比成功叙事更能体现一个 PM 的水平**——因为成功有时候是运气，失败暴露你的判断力。

#### 失败叙事的 5 步框架（**S-CRAFT**）

```
S - Situation: 简单背景，10 秒带过
C - Challenge: 明确这件事**为什么困难**（这一步很多人跳过——但跳过就会让面试官以为这事不难）
R - Response: 你做了什么决定（关键：交代你**没选什么**比交代你选了什么更重要）
A - Aftermath: 结果是什么（不要美化，老实说）
F - Frame: 你怎么 reframe 这次失败（这是核心）
T - Takeaway: 你提取了什么原则
```

注意 F-T 是失败叙事独有的。这两步把"我搞砸了"转化成"我从中提取了什么思考密度"。

#### 失败叙事的反例

❌ "我最大的失败是太追求完美" —— 这是装失败，面试官秒识破，最掉档。
❌ "我和团队意见不合，我没坚持自己的想法" —— 把失败变成抱怨，暴露 emotional 不成熟。
❌ "项目被砍了，我很难过，但我学到了团队合作很重要" —— 啥都没说。

#### 失败叙事的"惊艳"档示范

> "我研一带过一个学生 Agent 创业项目，目标是做'帮学生选课的 Agent'。我们做了 3 个月——RAG 接 100 多门课的描述，对接学校的选课系统 API，整个 demo 在我们小圈子内表现很好。
>
> 但 launch 的时候惨败——上线第一周 50 个用户，第二周 30 个，第三周 8 个。问题在哪？
>
> 当时我以为是技术问题，花了两周优化模型——没用。然后我做了一件事：去找那 8 个还在用的人聊 30 分钟。结果发现一件事——**他们都是不会自己规划的人**。会规划的人压根不需要 Agent；不会规划的人来了，但**他们没有'输入'能力**——他们对自己想要什么也不清楚，没法告诉 Agent 自己的偏好，于是 Agent 给的建议在他们看来都'差不多'。
>
> 这件事让我学到一个很硬的道理：**Agent 产品的瓶颈不在 Agent，在 user 的输入意愿和输入质量**。我现在看任何 'AI 助手' 类产品，第一个问题永远是'用户能不能、愿不愿意给出有效输入'——如果答案是'不能'或'不愿'，技术再好都是空。
>
> 这个项目本身失败了，但这条原则后来救了我两次——研二我加入一个研究项目，他们想做'智能学生写作辅导'，我提出的第一个问题就是'让学生主动描述他要什么'这件事的可行性，结果发现压根行不通，团队及时转向，省了 6 个月时间。"

注意这段做对了什么：
- **明确了为什么难**（C 步骤——选课领域看似简单实则用户输入难）
- **交代了"没选什么"**（没选大改技术、没选放弃、选了找用户聊）
- **没美化结果**（老实说"惨败"）
- **Reframe 不是抱怨，是提取原则**（"瓶颈不在 Agent 在 user 输入"）
- **原则在后续被验证**（救了下一个项目）—— 这一句话价值千金

## ④ 自我介绍：30s / 60s / 2min 三档

### 为什么要 3 档
不同场景需要不同长度——
- **30s**：电梯遇到 / 群面 / 领导 skip
- **60s**：HR 一面 / 技术面开场
- **2min**：直属老板 / 终面

### 设计原则

每一档都要做到 4 件事：
1. **首句钩子**（前 5-7 个字决定对方专注度——心理学的首因效应）
2. **主旋律**（你过去在干嘛）
3. **能力锚点**（1-2 个具体的代表作）
4. **为什么是现在 / 这家公司**（叙事主轴的下一站）

### 30s 模板（首句钩子 + 主旋律 + 一个锚点 + 下一站）

```
"我[首句钩子]——[主旋律 1 句]。最近做的事是[一个具体锚点]。这次想加入[公司]的原因是[1 句下一站]。"
```

#### 火山方舟例（30s）

> "我一直在做一件事——**把大模型能力翻译成具体行业能用的产品**。研一在 X 实验室做过医疗 RAG，最近在帮一个电商客户做导购 Agent 的 PoC。这次想来火山方舟，是因为你们 Coding Plan 和 Agentic RAG 这两条线上做的事，是我'翻译'能力能规模化的最大场景。"

约 30 秒。**首句钩子**是"一直在做一件事"——它逼面试官想"哦，这件事是什么"，专注度立刻上来。

### 60s 模板（30s + 一个深度故事钩子）

在 30s 基础上，加一段 **15-20 秒的"故事种子"**——埋一个让面试官**忍不住追问**的钩子。

```
"...[30s 内容]...

具体讲，最让我有感觉的是 [项目 X] —— 我们一开始以为问题是 [A]，做了一段时间发现真正瓶颈在 [B]。这让我意识到 [一句原则]，这个原则后来在 [另一个场景] 又一次得到验证。

所以这次来面试，我特别想看看[一个具体的、和岗位相关的好奇点]。"
```

埋钩子的核心：**让面试官有 2-3 个可以追问的点**，这样面试就成了你引导的对话，不是面试官单向考你。

### 2min 模板（60s + 一段思考密度展示）

2min 自我介绍很多人讲不好——讲多了变流水账，讲少了又显空。

正确做法：**60s 内容 + 60s 思考密度**。

后 60 秒围绕一个问题展开："**我对这个行业 / 这个岗位的本质看法是什么**"——例如：
- 你对 AI PM 这个职业的本质判断
- 你对 Agent / RAG / Multi-Agent 这条赛道的判断
- 你对模型能力 vs 应用层 价值分配的判断

不需要大词，但要有非显然的判断。**这 60 秒是面试官评估你"思考密度"的最大窗口**。

#### 反例

❌ "我叫 XX，毕业于 XX 大学 XX 专业，我做过 ABCD 项目..." —— 这是简历朗诵不是自我介绍。
❌ 自我介绍 3 分钟还没讲完 —— 失控。
❌ 全程没看面试官眼睛 —— 心理学的首因效应不只是听觉的。

## ⑤ 黑话校准（Bourdieu 文化资本的具体落地）

### 概念
你说话的方式 = 你的派系归属。这不是肤浅——这是**进入一个场域要带的文化资本**。

### 三大派系黑话表

| 概念 | 北美派 | 大厂派（字节/阿里系） | 创业派 |
|---|---|---|---|
| 衡量产品成功 | north star metric | 北极星指标 / 核心指标 | retention / 留存曲线 |
| 模型不准 | hallucination | 幻觉 / 模型生成错误 | 幻觉率 |
| 让模型按规矩答 | grounding / constitutional | 模型对齐 / 价值观对齐 | 对齐 |
| Agent 系统 | agentic harness / tool-using agent | 智能体 / 数字员工 | Agent 框架 |
| 评测 | eval / LLM-as-judge / red-teaming | 评测 / 人工标注 / 测评 | eval pipeline |
| 微调 | fine-tune / SFT / DPO / RLHF | 精调 / 二次训练 | SFT/DPO |
| 找需求 | jobs-to-be-done | 用户场景 / 用户痛点 | 找 PMF |
| 发布节奏 | ship fast / iterate | 小步快跑 / 灰度 | ship |
| 决策 | leverage / north star | 抓手 / 颗粒度 | 主线 |
| 退步 | regression | 回归 / 退化 | 倒退 |
| 战略 | bet / hard problem | 押注 / 硬骨头 | 主线 / 大方向 |
| 团队组织 | DRI / single-threaded | OKR / 双月 / 拉通 | 主线 + 卫星 |

### 校准策略（按目标公司）

skill 在 L1 战略层输出**一份"黑话校准卡"**：

```
🗣 黑话校准（针对 [公司名]）

✅ 推荐使用（这是这家公司的"自家话"）：
- [词 1]：场景示例 [...]
- [词 2]：场景示例 [...]
- ...

⚠️ 谨慎使用（用错了显得"不是这个圈的"）：
- [词 X]：[原因]
- ...

❌ 不要使用（反派系黑话）：
- [词 Y]：原因 [...]
- ...
```

### 火山方舟例

```
✅ 推荐：底层逻辑 / 抓手 / 颗粒度 / 复盘 / 拉通 / 客户标杆 / 落地 / 行业 know-how / Agentic RAG / VikingDB / 解决方案
⚠️ 谨慎：grounding / constitutional （太北美派，AI 解决方案 PM 岗用不上） / DRI （字节系不太用这词）
❌ 不要：增长黑客 / 私域转化（这岗位是 B 端解决方案，不是增长 PM）
```

### 校准的红线

- **不要装腔**：用黑话是为了让对方觉得"你是自己人"，不是炫耀。一句话挤 5 个黑话词，反而显得装。
- **要懂含义**：用了某个黑话，面试官可能追问——你必须能回答清楚。例如说了"agentic harness"，面试官问"你怎么理解 harness 和 framework 的差别"，你得能答。
- **简历也要校准**：简历里的措辞和你面试时的话语应该是一致的派系。
