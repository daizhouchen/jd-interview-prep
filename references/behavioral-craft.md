# 行为题工艺：场景驱动选模板 + 失败叙事 + 信号管理

行为题（"讲一次你..."类的问题）是面试评估**软实力**的主战场。但 99% 的面试准备教的是 STAR 模板套娃——**这是入门，不是工艺**。

这份 reference 教 skill 怎么把行为题答得有判断力——核心是 4 件事：
1. 场景 → 模板的决策（不只 STAR）
2. 失败叙事的特殊工艺
3. 隐藏信号管理（Big Five 在行为题里怎么显形）
4. 三档对比的高频题库

---

## ① 4 个模板及其适用场景

行为题不只一种，模板也不只 STAR。**用对模板比熟练背 STAR 重要 10 倍**——错位用模板会暴露 PM 经验不足。

### 模板 1 · STAR（最通用，但有限制）

```
Situation：背景（10-15 秒）
Task：你的任务（5-10 秒）
Action：你做了什么（30-40 秒，重头戏）
Result：结果是什么（10-15 秒）
```

**适用**：单事件、有明确开始结束、有可量化结果的故事。
**例**："讲一次你 own 一个项目从 0 到 1"

**STAR 的盲区**：
- 不擅长讲"长周期、多次起伏"的故事
- 不擅长讲"被砍/失败"的故事——R 这一步会很尴尬
- 不擅长讲"多人协作"的故事——A 全是"我"听着像独角戏

### 模板 2 · CAR（更精炼，适合短答场景）

```
Context：背景（10 秒）
Action：你的应对（45 秒）
Result：结果（10-15 秒）
```

**适用**：HR 一面这种轻量场景；或被问"再讲一个例子"时的快速回答。
**例**："你能不能再讲一个你处理冲突的例子"

**vs STAR**：把 Task 合进 Context，更紧凑。

### 模板 3 · SOAR（领导力 / 主动性场景专用）

```
Situation：背景
Obstacles：你识别的障碍（关键，这一步是 STAR 没有的）
Actions：你的应对
Results：结果
```

**适用**：领导力题、主动推动题、跨部门协作题。
**例**："讲一次你主动推动一件没人推的事"

**为什么 SOAR 优于 STAR 这种场景**：因为这些题的核心是**"你识别了什么别人没看到的问题"**——没有 Obstacles 步，你把领导力题答成"我做了 ABC"，听起来像执行不像主动。

### 模板 4 · SBI（反馈/冲突场景专用）

```
Situation：具体情境（不抽象）
Behavior：你看到的具体行为（不是评价）
Impact：这个行为带来的影响（事实层面，不是情绪）
```

**适用**：被问"你怎么给反馈" / "你和别人冲突怎么处理" / "你怎么处理不同意见"。
**为什么不用 STAR**：反馈题的核心是**"你能不能区分行为和人"**——SBI 这个模板本身就是反馈框架（亚马逊和 Netflix 的 manager 培训都教这个），用它答能让你显得"懂团队管理"。

**例**：被问"你怎么给同事反馈"
> "我会用 SBI 模板：先讲 Situation——'上周三那个客户会上'；再讲 Behavior——具体行为，不评价人，比如'你在客户提问到 cost 时，没等客户讲完就开始介绍我们的 pricing'；最后讲 Impact——'我观察到的结果是客户后面的几个问题都没问完，会议结束时他们的表情是有点拘谨'。这一套下来，对方拿到的是事实而不是评价，比'你不太会听客户'这种话好接受 10 倍。"

注意：直接说"我用 SBI 模板"反而成了一个加分点——因为它让你显得"懂方法论"。

## ② 模板选择决策树

```
被问的题是什么类型？
        │
        ├── 单事件成功故事 → STAR
        │
        ├── 短答补充 → CAR
        │
        ├── 领导力/主动性 → SOAR
        │   （关键词："主动推动"、"没人做"、"推动他人"）
        │
        ├── 反馈/冲突/沟通 → SBI
        │   （关键词："给反馈"、"冲突"、"不同意见"、"批评"）
        │
        └── 失败/挫折 → S-CRAFT （见下方）
            （关键词："失败"、"被砍"、"最难的"、"最大的失败"）
```

### 反例

❌ 用 STAR 答失败题：S "项目背景是 X" → T "我的任务是 Y" → A "我做了 Z" → R "项目失败了，我学到了 X" —— 太机械，R 一步尴尬到爆。
❌ 用 STAR 答冲突题：A 全是"我"——听起来像你单方面解决问题。
❌ 模板缝得太明显："让我用 STAR 框架来回答..."——这是新手错误，模板要溶进话里，不是宣告出来。

## ③ 失败叙事 · S-CRAFT（最高频考点专用）

详见 narrative-architecture.md 的"失败叙事工艺"章节。这里复述要点 + 补 3 档对比。

```
S - Situation 简单背景
C - Challenge 这件事为什么困难
R - Response 你做了什么决定
A - Aftermath 真实结果
F - Frame 你怎么 reframe（这是 STAR 没有的关键）
T - Takeaway 提取的可迁移原则
```

### 高频失败题三档对比

#### "讲一次你最大的失败"

**弱**："我最大的失败是太追求完美，导致项目延期。" —— 装失败，最掉档。

**合格**：见 narrative-architecture.md 的合格示例（学生 Agent 项目，讲了背景、做了什么、失败了、学到啥）。

**惊艳**：见 narrative-architecture.md 的"惊艳"示例（同一项目，但讲清了为什么难、提取了"Agent 瓶颈不在 Agent 在用户输入"的原则、原则在新项目得到验证）。

#### "讲一次你被砍掉的项目"

**弱**："我做的一个项目，老板说优先级降低就停了。"

**合格**："我做了一个项目，做了 3 个月，因为公司战略调整被砍。我学到了优先级管理的重要性。"

**惊艳**：
> "我研究生阶段在 X 实验室带过一个'AI 教学助手'项目，做了 4 个月，最后被砍。
>
> 当时我觉得很难——指导老师在两次月会都说'继续做'，所以团队投入度很高。但后来反推，**早在第 2 个月有 3 个信号其实就告诉我'这个会被砍'**：(1) 老师从'非常感兴趣'变成'还可以'；(2) 老师的注意力转移到另一个项目；(3) 学生用户测试反馈非常分裂——一半觉得有用一半觉得没意思。
>
> 但当时我看不懂这些信号，因为我太投入'怎么把模型做得更好'。
>
> 这件事让我形成了一个习惯：**做项目时每月强制做一次 'kill check'**——不是'这个项目怎么做得更好'，而是'如果今天我才接到这个项目，我会做吗？'。这个简单的 reframe 让我后来又一次主动停止了一个走偏的项目，省了团队 2 个月时间。
>
> 失败的项目本身价值不大，但它教我的'kill check' 习惯，我觉得是这 4 个月最值的产出。"

注意"惊艳"档做对的：
- 不抱怨老板
- 不归因外部（"战略调整"）
- 自己抽出 3 个早期信号——展示**复盘深度**
- 提取的不是空话（"重视优先级"），是具体可执行的习惯（"每月 kill check"）
- 习惯**已经在新项目中得到验证**——这一句话是金子

#### "你最大的弱点"

**弱**："我太追求完美了。" / "我太投入工作了。" —— 装失败。

**合格**："我有时候在不熟悉的领域决策慢，因为想多收集信息。" —— 真实但平。

**惊艳**：
> "我现在最在意的弱点是 **'容易在数据信号弱的时候过度依赖直觉'**。
>
> 具体说——AI 产品很多时候没法做大规模 A/B（用户量不够 / 反馈滞后），这种情况下 PM 容易陷入'我觉得这样好'的直觉决策。我自己复盘过，去年有 3 次决策事后看是过度依赖直觉，其中 2 次幸运是对的，1 次错了浪费了 3 周。
>
> 所以我现在养成的对策是：当数据弱时，强制自己**写下'如果我错了会有哪些信号'**——把直觉决策变成可证伪的 hypothesis。这个习惯让我决策速度变慢一点，但后悔率明显降了。
>
> 这个弱点我不会说彻底克服了——我觉得它和 PM 的工作场景本身耦合很深，我能做的是**让它的破坏力可控**。"

为什么这是惊艳：
- **真的在讲弱点**——不是装（"太追求完美"）
- 弱点和岗位有关（AI PM 工作场景的真实困境）
- **有具体频率**（"去年 3 次"）
- **有可执行对策**——而且承认弱点不能消除只能管理（这一句价值千金，显示成熟度）

## ④ 隐藏信号管理（Big Five 在行为题里怎么显形）

### Big Five 是什么
心理学的人格五维度：
- **O (Openness)** 开放性——好奇、爱学
- **C (Conscientiousness)** 尽责性——可靠、守时、按计划
- **E (Extraversion)** 外向性——主动表达、社交能量
- **A (Agreeableness)** 宜人性——合作、共情
- **N (Neuroticism)** 神经质——情绪波动（**反向**——低 N 是稳定）

面试官**不会显式问**这些——但每个回答都会被打分。AI PM 这个岗位的隐性评分倾向（基于真实面试官反馈）：

| 维度 | 偏好 | 怎么在行为题里显示 |
|---|---|---|
| O 开放性 | 高 | 提到读论文/技术博客、提到从其他领域迁移想法、对新概念好奇 |
| C 尽责性 | **高（最关键）** | 讲项目时讲清里程碑、讲 timeline、讲"我做了 X 让事情不掉链子"——AI PM 极看重 |
| E 外向性 | 中等 | 提到"和团队讨论""主动找客户聊"——但不要过度，过外向会显得不深思 |
| A 宜人性 | 中高 | 讲冲突时讲清"我理解对方的角度"——不能太低（爱怼人）也不能太高（没主见） |
| N 神经质（低） | **低（稳定）** | 讲失败/压力时**不流露情绪化抱怨**——是核心信号 |

### 反例（高 N 信号）

❌ "上家公司很黑，让我加班还不给加班费" —— 高 N 信号，扣分严重。
❌ "项目被砍那段时间我很难过，每天睡不着" —— 真实但偏 N，谨慎使用。
❌ "我老板很难搞" —— 任何抱怨味道都是高 N 信号。

### 怎么主动制造低 N + 高 C 信号

讲压力 / 失败 / 冲突的故事时，遵循"事实 + 复盘 + 原则 + 对策"四步：
1. 事实层面陈述（不抱怨）
2. 复盘自己的角色（不归因外部）
3. 提取一个原则
4. 给一个具体对策（说明你已经在改）

这套下来 = 低 N（情绪稳定）+ 高 C（有 mechanism 应对）+ 中高 A（不甩锅）的复合信号。

## ⑤ 高频行为题三档对比库

### "讲一次你和同事意见不合"

**弱**："我们意见不一致，最后用了我的方案，证明我是对的。"
- 高 N（爱怼）+ 低 A（不合作）+ 暴露你不会处理冲突

**合格**："我们方案不同，我尝试理解他的角度，最后我们妥协选了一个折中方案。"
- 安全但平庸，没体现思考密度

**惊艳**：
> "研究生阶段做项目时和组员有过一次方向分歧——他想用 fine-tune 提升效果，我倾向先 RAG。
>
> 我先做了一件事：**没急着说服他**，反而问他'你判断 fine-tune 比 RAG 好的依据是什么'——他的依据是'我看到一篇论文 X 说 FT 比 RAG 好 5%'。我看了那篇论文，发现它的 setup 和我们差很多——我们数据量只有 200 条，而论文是 50k。
>
> 我没有说"你错了"，而是和他一起**列了一个判断标准**：先选 5 个我们最关心的 case，分别用 RAG 和 FT 跑一周，看哪个赢。一周后 RAG 在我们 case 上明显更稳，他也认了。
>
> 这件事让我形成的原则是：**在团队冲突里，'谁对'不重要，'用什么方法判断'更重要**——把人对人的争论变成可验证的标准，所有人都好下台阶。这个原则后来我用过两三次都很 work。"

为什么惊艳：
- 没有把对方讲傻
- 没有说服 = 用证据 = 显得成熟
- 提取的原则可迁移
- 原则被验证

### "你最骄傲的一件事"

**弱**："我做的某个项目获得了某个奖。" —— 凭奖项不凭判断。

**合格**：项目背景 + 你做了什么 + 拿了什么结果。 —— 标准 STAR 结构。

**惊艳**：选一件**展现你思考密度而非外部认可**的事。
> "我最骄傲的不是项目本身，而是我从一个项目里**抽出了一个原则、用这个原则改变了我后续工作方式**。
>
> 具体讲：研一做 RAG 项目时发现用户和我们的 metric 严重脱节（hit rate 高但用户不满）。这件事本身没什么特别，但**这个'代理指标偏移'的概念让我后来无论做什么 AI 应用，第一周都强制和真实用户做 30 分钟'看他用'再设计 metric**——这个工作方法救了我后续两个项目，省了大量返工。
>
> 我觉得'拿了什么结果'容易，'形成了什么习惯' 难——后者才是骄傲的事。"

### "你为什么觉得自己适合这个岗位"

**弱**："我对 AI 感兴趣，做过相关项目，希望能贡献。" —— 通用模板。

**合格**：扣 JD 三个要求，每个给一个对应的经验。

**惊艳**：扣 JD + 给一条**JD 没要但你能给的**稀缺价值。
> "JD 写了三个核心要求：(1) 懂 RAG/向量库等大模型应用——我研究生做过医疗 RAG 完整 stack；(2) 配合做客户落地——我帮过一个电商客户做导购 Agent PoC，跟过完整的 sales 闭环；(3) PPT 和方案能力——我组里 3 次大型答辩都是我主笔，PPT 我可以发过去你看。
>
> 三个 JD 要求我都对得上。但我想多说一句**JD 没明说但我觉得我能多给的**——我的 RAG 经验里踩过的坑（比如 chunk size、eval 偏移、cost 优化），让我在和客户讨论时能讲'**坑在哪 + 怎么避**'，而不是讲'我们能做'。这种在 sales 阶段就能展示技术深度的能力，我觉得对'解决方案 PM'这个角色比 JD 列的几条更稀缺。"

注意末尾这一段——**主动给 JD 没要但你能给的稀缺价值**——这是把"匹配"变成"超出预期"的关键。

## ⑥ 5 个 AI PM 高频行为题清单（直接套用）

skill 在 L2 战术层输出 4-6 个针对 JD 的行为题，每个三档对比。

通用清单（按出现频率排序）：

1. **"讲一次你最大的失败 / 被砍的项目"** —— 必考，用 S-CRAFT
2. **"讲一次你 own 的项目从 0 到 1"** —— 高频，用 STAR/SOAR
3. **"你和同事意见不合怎么处理"** —— 高频，用 SBI 或 SOAR
4. **"你最大的弱点"** —— HR 必问
5. **"你为什么从上家离职 / 为什么选我们"** —— HR 必问
6. **"你 5 年规划"** —— 终面 / skip 高频
7. **"你怎么处理 deadline 紧 / 多任务并行"** —— 实习 / 校招高频
8. **"讲一次你跨团队协作"** —— 中级以上必问
9. **"你欣赏的人是谁 / 你的价值观"** —— 终面专属
10. **"你对 AI / 这个行业最近的看法"** —— AI PM 必问，详见 ai-pm-canon.md 考题 7
